# apps/mobile — Expo SDK 58 + Expo Router + Uniwind (Tailwind v4) + React Native Reusables

Read the root `AGENTS.md` first. This app is **UI + platform wiring only**: data fetching, auth
and form schemas come from `@workspace/core`; API types from `@workspace/api-client`.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. Before writing code that touches an Expo, EAS or
React Native API:

1. Check the `expo` major version in `package.json` (currently 58).
2. Read the matching docs: `https://docs.expo.dev/versions/v58.0.0/`, or start from https://docs.expo.dev/llms.txt (append `.md` to any docs URL).


## Rules

- Navigation: Expo Router only. Auth gating is done with `Stack.Protected` in `src/app/_layout.tsx` based on `useAuthStore`; do not add manual redirects in screens.
- Data: hooks from `@workspace/core/<feature>`. Missing hook → add it to `packages/core`. Never call `axios`/`fetch` directly for the backend. Lists use `FlatList` + `RefreshControl` with `onEndReached` → `fetchNextPage()` (cursor pagination); call `useRefreshOnFocus(refetch)` on tab screens. Destructive actions confirm with `Alert.alert` (native, no extra dependency).
- Forms: take `{ form, onSubmit }` from the core form hook (`useLoginForm()`…) and render `FormInput` + `FormRootError`; wire submit as `onPress={() => onSubmit()}`. Never re-implement submit or error mapping in a screen.
- UI: React Native Reusables (`npx @react-native-reusables/cli@latest add <name>`), never hand-copied. Answer **No** to overwrite prompts. Text must be wrapped in `<Text>` from `@/components/ui/text`.
- **After adding an RNR component, align it** (typecheck points at the first two):
  1. Icons: RNR ships `lucide-react-native`; replace with the Hugeicons icon the web version uses (`<Icon icon={Cancel01Icon} />`, from `@hugeicons/core-free-icons`). Lucide is not installed.
  2. Shape/size: copy the maia classes from the same component in `apps/web/src/components/ui` (e.g. `rounded-4xl`, `h-9`, flat variants, same size/variant names). Drop DOM-only selectors (`has-*`, `aria-*`, `group/*`) or keep them inside `Platform.select({ web })`.
  3. Run `pnpm theme` (root) — the CLI must not have written tokens into `global.css`.
- Styling: Uniwind = Tailwind **v4** syntax, same utilities and tokens as web. Color props on native components use the `accent-` prefix (`placeholderTextColorClassName="accent-muted-foreground"`).
- Fonts: one family (`fontFamily.sans` from `@workspace/theme`) with real weights loaded in `lib/fonts.ts`; `font-medium`/`font-semibold` work as on web. `Text` and `Input` apply `font-sans`.
- Text: `useTranslation()` from `@workspace/i18n`; never hard-code strings. Theme/language: `usePreferencesStore` (root layout forwards theme to `Uniwind.setTheme`).
- Tokens are stored in SecureStore (`src/lib/storage.ts`); never use AsyncStorage for secrets.
- Env: read only through `src/lib/env.ts` (validated; `process.env` elsewhere is a lint error). `EXPO_PUBLIC_API_URL` is the origin only; in development `localhost` is swapped for the Metro host, so physical devices on the same network work. Development values are in the committed `.env.development`; builds get theirs from the EAS environment of the profile.
- Forced update: the API answers `426 app_update_required` when `X-App-Version` (sent by `lib/setup.ts`) is below `MIN_APP_VERSION`; the root layout then shows `AppUpdateScreen` instead of the app. JS-only fixes ship over the air with `eas update --channel <profile>` (`expo-updates`, `runtimeVersion` = app version); native changes need a store build.
- Errors are reported to Sentry (`lib/monitoring.ts`, root layout wrapped in `Sentry.wrap`) when `EXPO_PUBLIC_SENTRY_DSN` is set; never send tokens or personal data in extras.
- `ios/` and `android/` are generated (CNG). Never create or edit them; configure via `app.config.ts` and config plugins. Store identifiers come from `APP_ID` (suffixed `.dev` / `.preview` per `EXPO_PUBLIC_APP_ENV`, so variants install side by side), the EAS project from `EAS_PROJECT_ID`.

## Device capabilities

A capability = config plugin + permission text in `app.config.ts`, setup in `src/lib/<capability>.ts`,
a hook that exposes `{ status, …, request }`, and an explicit user action before the first
permission prompt (never prompt on launch without context).

- **Push notifications** (`expo-notifications`): `usePushRegistration()` is mounted once in the
  signed-in tab layout. It gets the Expo token (physical device + `EAS_PROJECT_ID` required) and
  registers it with the API through `useRegisterPushDevice`, again whenever the language changes
  (pushes are rendered server-side per device locale). Tapping a notification with
  `data.url` navigates there. Logout unregisters the device (core `useLogout`). Push text is never
  written in the app: the API sends it.
- **Location** (`expo-location`): `useCurrentLocation()` asks foreground permission on demand and
  returns one position. Background location needs a task, `isAndroidBackgroundLocationEnabled`
  and a store-review justification: add it only with a real requirement.
- Adding another (camera, biometrics…): `npx expo install`, add the plugin and permission strings,
  follow the same shape, then rebuild the dev client (Expo Go lacks custom native code).

## Releases

`eas.json` profiles: `preview` (internal APK / ad-hoc iOS) and `production` (AAB + store IPA,
`autoIncrement`, remote app versions). Pushing a tag `v*` runs `.github/workflows/mobile-release.yml`:
EAS builds production (both platforms) + preview APK and attaches them to the GitHub Release.
Signing credentials are managed by EAS, never committed. Details: `docs/deployment.md`.

## Commands (from `apps/mobile`)

```bash
npx expo install <package>   # ALWAYS for native/Expo deps (SDK-compatible versions)
pnpm dev                     # expo start (press i / a / w)
pnpm typecheck               # lint runs from the root: `pnpm lint`
pnpm run doctor              # expo-doctor (plain `pnpm doctor` hits pnpm's built-in command)
npx expo export -p ios -p android   # verify bundling without a device
```

After adding a library with native code, a development build is needed (`npx expo run:ios|android` or `eas build --profile development`); Expo Go only has bundled modules.
